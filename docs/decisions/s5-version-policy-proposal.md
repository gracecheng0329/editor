## A. 自動快照與重試

- 首個尚未被快照涵蓋的已接受修訂到達後 **120 秒**觸發；持續編輯不延後該到期時間。沒有新修訂不建立。排程在服務端持久化，不依賴瀏覽器在線。正常服務下仍以 **300 秒**作為最後修訂被快照涵蓋的最長等待驗收門檻。
- 失敗後依序等待 **10、30、60、120、300 秒**重試，之後每 **300 秒**重試，沒有自動放棄次數。排程及失敗狀態跨協調者重啟保存。手動重試可提早執行，但沿用相同去重鍵。
- 恢復時補建當下最新已接受修訂；不承諾重建故障期間每一個中間版本。自動快照以文件／世代／修訂去重，多會話不造成重複。里程碑使用獨立操作 ID，可立即建立。
- 保存失敗顯示「版本保存失敗，將於…重試」；失敗或僅收到通知都不能顯示成功。新修訂的正常排程不被先前較晚的重試延後。服務恢復後至遲於下一個 300 秒重試補建；若已有健康檢查恢復訊號則立即重試。
- 快照 bytes／schema／修訂與 Postgres 可讀索引必須達成正式保存契約後才對使用者顯示成功。索引補寫使用原版本 ID；不得建立重複版本。還原切換後的索引失敗以 Durable Object 已記錄結果為準補寫，不能回退畫布。

## B. 保留上限及優先順序

每文件最多 **200 個**快照，三種配額獨立，不互相借用：

| 類型 | 最大數量 | 最大期間 | 自動清理保護 |
| --- | ---: | --- | --- |
| 自動快照 | 100 | 30 天 | 進行中還原引用的資料 |
| 里程碑版本 | 50 | 無自動期限 | 不由自動清理刪除；滿額時拒絕新增 |
| 還原前快照 | 50 | 30 天 | 建立後 7 天內不由自動清理刪除；另保護進行中還原引用 |

- UTC 以保存成功時間計算。達到 `createdAt + 期間` 即過期；七天保護於相同時間邊界結束。順序：先排除進行中還原引用；再處理達期限者；再為數量上限清理最舊的可清理項目，時間相同依不可變版本 ID 升序。里程碑不受其他類型的清理壓力影響。
- 保護不提供超過 200 的例外。新增前由單一協調者原子保留配額；若還原前 50 個都受保護，**拒絕新的還原，維持目前畫布／世代**。里程碑 50 個滿額時拒絕新增，不暗中刪除舊里程碑。UI 說明滿額原因及可採取的清理動作。
- owner 可在明確確認後手動刪除未被進行中還原引用的版本（包括里程碑及七天內的還原前版本）；「保護」特指免於自動清理。editor 不取得刪除版本資格。手動清理入口與對應授權測試列入後續版本票。
- 清理至少每 **24 小時**執行一次，並在建立新版本前執行。過期版本立即從可用清單隱藏並拒絕新的預覽／還原；bytes 的實體回收最長可延後 24 小時。進行中還原需要的資料保留至該持久操作明確完成／安全失敗，不能只因 lease 到期就回收。
- 清理與還原的驗權、來源版本 pin 及配額保留須由協調者序列化；任何一步失敗不能留下已切換但無還原前快照的狀態。重啟先恢復操作，再解除 pin。無法判定的操作保持 pin 並呈現恢復中，不能猜測已完成。

## C. 清理後公開回應與 UI

- 清單排除已過期／已清理版本。已授權且屬於該文件的清理 tombstone 保留 **30 天**，預覽／還原回 `410 VERSION_GONE`，之後回 `404 VERSION_NOT_FOUND`。無權讀取者一律沿用文件存取拒絕回應，不能藉 tombstone 查出版本或文件存在。
- 已開啟的預覽遇到 410，顯示「此版本已清理，無法預覽或還原」，移除可還原狀態並刷新清單；不回退到另一版本或顯示成功。已被使用者下載／顯示過的內容無法遠端收回。
- 配額受保護版本占滿回 `409 VERSION_LIMIT`；另一還原正在執行回 `409 RESTORE_BUSY`，可重試但不假報成功。取得有效 pin 後的進行中還原，不因目標之後達到保留期限而失去來源 bytes。
- tombstone 與還原操作去重紀錄不是快照，無畫布內容，不占 200 個配額；操作結果另保留 **30 天**。超過期間的舊 operation ID 不可直接重執行：回 `410 OPERATION_EXPIRED`，必須使用新操作 ID 並重新確認。服務須保有不可重用的操作 ID 標記，避免舊請求再次切換世代。

## D. SDK／schema 相容

- 第一版只承諾目前固定的 **tldraw／sync／tlschema 5.5.2 與本專案已註冊畫布 schema**。快照保存 SDK 版本、完整序列化 schema、文件修訂與世代。套件版本相同也不跳過 schema／record 驗證。
- 可預覽／還原的條件：schema 在部署版明列的相容矩陣內，且可在隔離 store 完整載入並通過 record／binding 驗證。預覽不連協作房間；還原切換前再做服務端驗證。
- SDK／自訂 schema 每次升版前，必須以保留期內的已支援快照 fixtures 驗證預覽、還原、重新保存及 bindings。只允許已測試並明列的單向遷移；在副本上執行，原快照不覆寫。提供「此版本需轉換」提示，還原前明確確認轉換；不默默嘗試載入未知 schema。
- 未知、較新、缺遷移或載入驗證失敗時回 `409 SNAPSHOT_INCOMPATIBLE`；UI 顯示無法預覽／還原及所需支援版本，不切換世代、不修改在線畫布、不刪除原快照。不承諾升版後可降版或舊快照永久相容。
- 若升版未通過既有支援矩陣，先阻擋發布；需要縮減支援範圍時另取得使用者決策，不能由實作代理暗中改變本政策。

## E. 後續票直接採用的驗收案例

| 情境 | 必須觀察到的結果 |
| --- | --- |
| 最後一次修改後停止／持續編輯 | 120 秒排程不被重設，健康服務 300 秒內有涵蓋修訂的自動快照 |
| 無修訂、多會話、同請求重送 | 無空快照、不重複保存相同自動修訂或相同操作 |
| 連續保存失敗及協調者重啟 | 10/30/60/120/300 秒重試階梯及下一次排程持久化；不假報成功 |
| 服務恢復與故障期間多次修改 | 下一次重試保存最新狀態；不要求重建中間版本 |
| bytes 成功、索引失敗或回應遺失 | 原版本 ID 補寫／查回；同操作不產生重複或再次切換 |
| 第 100/101 個自動快照、30 天整點 | 保留數量最多 100、過期不可新預覽；相同時間用版本 ID 決定順序 |
| 第 50/51 個里程碑 | 第 51 個拒絕並說明配額，不刪除任何既有里程碑 |
| 第 50/51 個還原前快照、7 天整點 | 保護中的滿額拒絕新還原；保護到期後才按順序自動清理 |
| owner／editor 手動刪除、跨文件版本 ID | 僅 owner 可刪除，跨文件拒絕；進行中還原引用不能刪除 |
| 過期來源與還原同時開始、清理中崩潰 | 已取得 pin 的還原可完成；未取得者拒絕；重啟先恢復操作，不誤刪 |
| 選中的版本已清理、tombstone 期限邊界 | 410 顯示已清理並停用還原；30 天後404；無權者不洩漏存在 |
| 支援 schema、未知／較新／損壞 schema | 支援者可隔離預覽；其餘409，畫布／世代保持原狀 |
| 已驗證遷移與缺少遷移 | 副本轉換並確認後才還原；原始 bytes 不變；缺遷移拒絕 |
| 還原前保存失敗／切換後索引失敗 | 前者原畫布與世代不變並恢復寫入；後者依 DO 已記錄結果補寫 |
| 相同／不相同 operation ID、30 天後重送 | 同 ID 結果一致，不同目標409；過期 ID 410，不重複切換 |

測試透過正式版本 HTTP 服務契約及獨立 browser contexts，使用真實 Durable Object／Supabase；故障注入限定測試環境的服務邊界，不 mock 同步合併結果。正式 UI 示範及部署 smoke 仍是各實作票的交付條件。
