# 分開畫布與產品資料的權威來源

畫布需要高頻協作與一致的房間狀態，留言及文件成員則需要獨立查詢與授權，因此由 Durable Object 持有權威畫布、修訂與有效世代，Supabase Postgres 持有身分關聯、文件中繼資料、權限、留言與版本快照／索引。相較將畫布逐筆寫入一般資料表或讓 SDK 同時保存留言，此分工沿用專用畫布同步引擎與關聯資料授權能力，並避免同一資料有兩個可互相覆寫的來源。

Supabase Realtime 僅負責留言變更通知，漏接後以 Postgres 補讀；Postgres 保存的畫布世代若存在，只是可重建索引。代價是版本保存與還原涉及兩個服務，須由單一協調者記錄進度、去重及補寫，不能假設有跨服務原子交易；詳細失敗行為見 [總規格](../specs/001-collaborative-architecture-whiteboard.md)。
