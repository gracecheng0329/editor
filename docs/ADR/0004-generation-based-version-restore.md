# 以畫布世代切換處理版本還原

同一文件允許離線修改與在線還原，單純覆寫目前快照會讓舊編輯於重連後污染還原結果，因此由 Durable Object 唯一協調還原：暫停接受寫入、可靠保存還原前快照，再原子切換畫布與有效世代，最後補寫 Postgres 索引。舊世代寫入一律拒絕，仍存活頁面的待同步內容由使用者另存新文件或明確放棄；這比靜默重播安全，也保留使用者指定的原文件還原體驗。

代價是還原成為具有持久進度的操作，必須使用穩定操作 ID 去重，區分切換前失敗、切換後索引失敗與成功回應遺失；留言與權限不隨畫布回退。SDK 世代拒寫與待同步內容保留方式仍待 G0 驗證，重試／保留與相容政策已由 #15 於 2026-11-17 確認，尚須在 S5 實作及驗證；完整行為見 [總規格](../specs/001-collaborative-architecture-whiteboard.md)。

2026-11-17 的 #15 使用者確認補充：每文件最多 200 個快照，分為自動 100／30 天、里程碑 50 免自動清理，以及還原前 50／30 天且首七天免自動清理。進行中還原引用必須保護，但不突破上限；無可安全清理配額時先拒絕還原，原畫布與世代不變。清理後不可還原；SDK／schema 僅接受明列並驗證的版本／單向遷移，不能默默假設舊版本永遠相容。這以明確滿額拒絕換取還原前資料保證與有限快照儲存；詳細邊界、使用者確認及測試情境見 [#15 版本政策](../decisions/s5-version-policy-proposal.md)。
